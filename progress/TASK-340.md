# TASK-340 — the agent's reply is typed out as it is generated

## Done
- Hub (hub-dev): new additive RPC `GatewayService.AgentStepStream(AgentStepStreamRequest{request}) returns (stream AgentStepStreamResponse{oneof delta|result})` (wrapper request: buf lint forbids one request type for two RPCs; `buf breaking` green). Same ledger, key, fingerprint, rate limit and quota as `AgentStep` (either RPC replays the other). Anthropic adapter `StepStream` (SSE): a hand-written incremental reader takes the top-level `text` string of the `reply` tool from `input_json_delta` (escapes, `\uXXXX`, surrogates, split chunks; fuzzed); other tools, thinking and text blocks are never streamed. Deltas cut only between runes (PR #331 rule, twice), coalesced to ~64 B / 50 ms (checked when a chunk arrives, no timer), at most 4000 characters. The result is built exactly as `AgentStep` builds it (whole validation, sentence cut, seal, kept thinking turn, settle). Provider call on a detached context: a client that leaves does not cancel it, the Hub settles once and stores. `HUB_PROVIDER_STREAM` (default on) off, a JSON answer from the gateway, and a replay send the result only. ADR-0026 addendum «streamed reply», ADR-0023 amendment, `docs/refs/anthropic.md`.
- Desktop (go-core): `hubclient.Step(ctx, req, draft)` reads `AgentStepStream`, hands the whole text so far to a callback (bounded again: valid UTF-8, no control characters except `\n` `\t`, 4000 runes); `unimplemented` falls back to unary `AgentStep` with the same request and key and is remembered per client; a stream without a result is offline (`ErrUnavailable`). Optional port `agentturn.Drafts`; `input/agent.Replies` publishes `Draft{Reply:true, CallID:"step:reply", Texts:[text]}` over the existing `Sink.Draft` / `agent:draft` (10/s throttle, last text wins), JSON gets `"reply":true`. A stored «Стоп» cuts the step's stream at once (`Driver.stopped` -> `Replies.Cut`). The draft is never stored, never in history, never sent to the planner (hard rule 3).
- Frontend: the reply draft is a growing bubble in the look of the final reply card (no caption), thin non-accent cursor, static under `prefers-reduced-motion`, the waiting dots hide while text arrives, «Стоп» stays in its row and is sticky at the bottom of the panel, a hidden `role="status"` says «Ответ печатается…» / «Ответ готов», the panel scrolls to the end when the final card replaces the draft (if the reader was at the bottom). After a user «Стоп» the shown text stays, muted, captioned «Ответ остановлен» (UI state only). A failure after a shown draft says «Ответ прервался. Можно повторить.».
- Tests: Hub (extractor, adapter vs unary equality incl. thinking turn, use case, handler, contract/transport), desktop (hubclient, agentturn, input/agent, input/wails, app, `desktop/tests/agent_stream_test.go` on real SQLite: stream, final differs, failure after deltas + Retry, Stop mid-stream + Continue replay, unimplemented fallback), frontend (`test/agentreplydraft340.test.mjs`).

## Decisions to confirm
- Only the `reply` tool argument streams. Text blocks (a preamble before tool calls, or a text-only answer) never stream: a preamble would look like the reply and then vanish. A text-only answer therefore appears whole.
- A replay sends the result only (no one-delta replay).
- A broken stream (no result) ends as offline and offers «Продолжить» (same key, free replay), not «Повторить» as the task text says: the outcome is unknown, so the stored step is replayed instead of paid again (ADR-0026).
- «Стоп» keeps the typed text on screen (muted, «Ответ остановлен»); this refines ADR-0026 «the draft is removed on Стоп» for the reply draft only (ux-expert must-fix: stopping must not destroy what the student read). Answer drafts are still removed. The backend cut may drop the last throttled chunk, so the kept text can be slightly shorter.
- Panel draft id is the fixed `step:reply` (the latest text always replaces the earlier one).
- A progress update lifts the draft cut for the reply draft only (answer drafts stay cut after a stop).
