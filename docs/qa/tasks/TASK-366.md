# TASK-366 — большой ответ по материалам и честное сообщение о сбое (проверка владельца)

Сначала переразверните Hub (новый промпт ответа v2, переспрос, промпт панели v9). Старый Hub этот шаг не покажет.
Версии: после обновления точно такой же вопрос, который Hub уже отверг за последние 24 часа, может ответить ошибкой (старая запись Hub). Переформулируйте вопрос.

## Проверка
1. С нуля: есть запись пары с готовым конспектом. В панели агента спросите «объясни, что было на этой паре». Ответ приходит целиком, с цитатами (их может быть больше трёх, длинные пункты не обрезаются); агент не пишет «материала нет».
2. В `desktop.log` (папка данных приложения) для этого запроса нет ошибки `answer`; если ответ был отвергнут, там видно разницу: «провайдер не ответил» или «ответ не прошёл проверку схемы».
3. Сбой: выключите сеть (или остановите Hub) и спросите то же. Агент отвечает сдержанно: «Произошла ошибка, ответ не получен. Повторить?» — без «материала нет», без «провайдер упал», без подробностей. «Повторить» после возвращения сети делает новую попытку.
4. Журнал Hub для успешного вопроса: `operation=answer outcome=ok`, при негодном первом ответе в логе виден один переспрос (`stream=true` тоже), больше одного не бывает.

## Ссылка на пару без https:// (дополнение к TASK-364)
5. «Сегодня» → «Добавить ссылку» → впишите `zoom.us/j/123`, Enter: ссылка сохраняется, на карточке «Подключиться» и адрес `zoom.us`. То же на странице предмета («Предметы» → предмет → «Изменить»).
6. `https://example.com` и `http://example.com` сохраняются как есть. `ftp://example.com`, `javascript:alert(1)` и `example.com:8080` отклоняются: под полем «Не похоже на ссылку на онлайн-пару. Пример: zoom.us/j/123 или https://… (только http или https, без порта).»
7. В поле серый пример «zoom.us/j/123 или https://…».
