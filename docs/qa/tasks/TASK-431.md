# TASK-431 — проверка владельцем: ссылки на пару по типу (ядро)

Это только Go-часть (предмет хранит общую ссылку и ссылки лекции, семинара, лабораторной; правило «ссылка типа пары, иначе общая»). Экран предмета и кнопки появятся в TASK-433, привязки страницы в TASK-432, агент в TASK-435…437. До них поведение приложения для владельца не меняется; проверять руками нечего, кроме регрессии.

Старт: холодный запуск на копии базы (миграция 0052 добавляет три пустых поля, общая ссылка сохраняется).

1. Откройте «Предметы» — у предмета с сохранённой ссылкой она на месте, «Подключиться» на «Сегодня» и в окне перед парой работает как раньше (открывается общая ссылка).
2. Проверка правила автоматическими тестами: `go test -race ./desktop/internal/domain/library/subject/... ./desktop/internal/cases/library/... ./desktop/internal/adapters/sqlite/... ./desktop/tests/...`. Они доказывают: лекция берёт ссылку лекции, иначе общую; семинар и практика — ссылку семинара, иначе общую, и никогда ссылку лекции; неизвестный тип — общую; без ссылок — «нет ссылки»; плохая ссылка отклоняется без изменений; в журнале только домен ссылки.
3. После TASK-433 проверьте вживую: задать разные ссылки для лекции и семинара одного предмета и нажать «Подключиться» на каждой паре.
