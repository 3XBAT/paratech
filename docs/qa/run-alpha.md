# Альфа-сборка: собрать, запустить, проверить

Пробная сборка десктопного приложения для Windows 10/11 (не инсталлятор: он в TASK-054).
Пометки: **[проверено]** — проверено запуском exe или тестом при подготовке этой инструкции;
**[владельцу]** — видно только на экране, проверить вручную.

## 1. Что нужно

- Go 1.26.9 или новее (версия указана в `paratech/go.work`). Более старый Go сам скачает нужную версию (`GOTOOLCHAIN=auto` по умолчанию).
- Node.js 22 с npm (как в CI).
- WebView2 входит в Windows 10/11, ставить не нужно.
- Права администратора не нужны. Скрипт ничего не устанавливает; из сети качаются только пакеты npm и модули Go (в их обычные кэши).

## 2. Сборка

Из корня репозитория в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\paratech\desktop\build-alpha.ps1 -Smoke
```

`-ExecutionPolicy Bypass` действует только на этот запуск, политика системы не меняется.

Что делает скрипт:
1. Проверяет, что `go` и npm (сначала `npm.cmd`, иначе `npm.exe`) есть в PATH (если нет — понятная ошибка, ничего не ставит).
2. `npm ci` и `npm run build` в `paratech\desktop\frontend` (интерфейс — главное окно и попап — встраивается в exe).
3. `go build -tags production -trimpath` с `CGO_ENABLED=0`, `GOOS=windows`, `GOARCH=amd64`. Переменные ставятся только на время сборки, потом возвращаются прежние значения.
4. Через `go version -m` проверяет, что exe собран с `-tags=production` и `CGO_ENABLED=0`.

Результат: `paratech\dist\alpha\learning-assistant.exe` (около 26 МБ). Папка `paratech\dist\` игнорируется git, после сборки `git status` чистый **[проверено]**.
Другая папка: `-OutDir $env:USERPROFILE\la-alpha`. Лучше брать папку внутри профиля: в папку в корне диска (`D:\...`) могут писать другие пользователи компьютера и подменить exe.

`-Smoke` (можно не указывать) — проверка без окна: exe запускается с `--headless` и папкой данных `paratech\dist\alpha\smoke-data` (не ваши реальные данные), скрипт ждёт до 60 с строк `instance lock acquired` и `background work started`, печатает лог (он же в `paratech\dist\alpha\smoke.log`) и останавливает процесс. Ошибка, если строк нет или в логе есть `level=ERROR` **[проверено]**.
Остановка в смоуке жёсткая (`Stop-Process -Force`): из PowerShell нельзя послать Ctrl+Break одному процессу без окна. Для тестовой папки это безопасно: блокировку снимает Windows, база при следующем запуске восстанавливается из журнала (файлы `-wal`/`-shm`). Мягкая остановка проверена отдельно (раздел 3).

## 3. Запуск и остановка

Из корня репозитория:

```powershell
.\paratech\dist\alpha\learning-assistant.exe
```

Открывается главное окно, в трее появляется иконка (стандартная иконка Wails, своей пока нет) **[владельцу]**.
Лог пишется только в консоль (stderr), в файл приложение само не пишет.

Флаги (`--help` печатает список) **[проверено]**:
- `--log-level debug` — подробнее (по умолчанию `info`; есть ещё `warn`, `error`). Отладочные строки самого Wails не пишутся: в них были бы аргументы вызовов, в том числе пароль почты и ключ Hub.
- `--data-dir $env:LOCALAPPDATA\la-test` — другая папка данных, например одноразовая для опытов. Путь только абсолютный. Тоже лучше внутри профиля, а не в корне диска (`C:\temp\...`): там её могут читать и менять другие пользователи компьютера.
- `--headless` — без окна и трея (для проверок).
- То же через переменные `LA_LOG_LEVEL`, `LA_DATA_DIR`, `LA_HEADLESS`; флаг важнее переменной.
- `--recorder` — служебный: так приложение само запускает рекордер (раздел 7); руками не запускать (по коду).
- Неизвестный флаг, неверный уровень или относительный путь: строка `desktop: config: ...` и код выхода 2.

Лог в файл (в Windows PowerShell 5.1 без мусора `NativeCommandError`):

```powershell
cmd /c ".\paratech\dist\alpha\learning-assistant.exe --log-level debug 2> .\paratech\dist\alpha\run.log"
```

Консоль при этом пустая; файл открыть после выхода из приложения **[проверено перенаправление на `--help`]**.

Остановка:
- трей, правый клик, `Quit` **[владельцу]**;
- Ctrl+C в консоли, из которой запущено приложение. Go обрабатывает Ctrl+C и Ctrl+Break одинаково: Ctrl+Break, посланный программой процессу `--headless`, дал в логе `gracefully stopped` и код выхода 0 **[проверено]**; Ctrl+C руками **[владельцу]**;
- крестик главного окна не выходит, а прячет окно в трей **[владельцу]**;
- при запуске двойным щелчком рядом откроется консоль с логом (exe консольный). Её закрытие тоже завершает приложение; надёжнее `Quit` в трее.

## 4. Где данные

`%LOCALAPPDATA%\LearningAssistant` (обычно `C:\Users\<имя>\AppData\Local\LearningAssistant`), создаётся при первом запуске **[проверено на одноразовой папке]**:
- `learning-assistant.db` — база SQLite (настройки, записи, задачи); рядом `learning-assistant.db-wal` и `-shm`, пока приложение работает или если его оборвали;
- `learning-assistant.lock` — блокировка «один экземпляр на папку»; файл не удаляется, это нормально;
- `artifacts\` — файлы приложения: `recordings`, `transcripts`, `models`, `exports` (кроме `recordings` пока пустые);
- `artifacts\recordings\<id>\chunk-NNNNNN.wav` — куски записи по 60 с; текущий, пока пишется, — `chunk-NNNNNN.wav.partial`. После «Остановить» рядом итоговая дорожка `artifacts\recordings\<id>.wav` (16 кГц, моно), куски остаются (по коду, **[владельцу]**).

Только в режиме с окном (по `docs/refs/wails.md` и коду Wails, при подготовке не запускалось):
- кэш WebView2 в `%AppData%\learning-assistant.exe` (папка по имени exe);
- служба уведомлений при старте пишет в реестр ключи `HKCU\Software\Classes\AppUserModelId\Learning Assistant` и `HKCU\Software\Classes\CLSID\<GUID>` (нужны, чтобы работали уведомления Windows), при выходе — `HKCU\SOFTWARE\Learning Assistant\NotificationCategories`. Данных приложения (записей, настроек) там нет.

Сброс: выйти из приложения (`Quit`), переименовать или удалить папку `%LOCALAPPDATA%\LearningAssistant`; при следующем запуске создастся пустая. Для опытов удобнее сразу `--data-dir` с одноразовой папкой.
По желанию можно удалить и папку `%AppData%\learning-assistant.exe`; ключи реестра выше для сброса трогать не нужно: оставить их безвредно (запуск с окном создаёт их снова). Убирать их имеет смысл только при полном удалении приложения, и это необязательно.

## 5. Как выглядит успешный старт

В начале каждой строки `time=...`. Запуск `--headless` на чистой папке **[проверено]**:

```
level=INFO msg="desktop core started" log_level=info headless=true
level=INFO msg="instance lock acquired"
level=WARN msg="speech recognition is not available: whisper-cli is not installed next to the executable"
level=WARN msg="transcription jobs wait in the queue until whisper-cli is installed next to the executable and the app restarts"
level=INFO msg="startup recovery finished" requeued=0 completed=0 failed=0 unregistered=0 corrupt=0 conflicts=0 errors=0
level=INFO msg="background work started"
level=INFO msg="recording recovery finished" recordings=0
```

Главное — `instance lock acquired` и `background work started`. Восстановление записей идёт в фоне, поэтому последние две строки могут идти в любом порядке. Две строки `WARN ... whisper-cli ...` без whisper-cli нормальны (раздел 6); вторая из них добавлена в TASK-060 **[тест]**.
С окном (по коду; **[владельцу]** сверить): `headless=false`, после предупреждения про whisper-cli строка `ui shell starting`, остальное в том же порядке; между ними могут быть строки оболочки Wails.
Планировщик и попап запускаются молча, своих строк при старте нет.
При выходе: `desktop core stopping`, затем `gracefully stopped` **[проверено]**.

Попап из трея (раздел 8) пишет в лог (по коду, **[владельцу]** сверить; названия занятий в лог не попадают):

```
level=INFO msg="ad-hoc recording prompt offered" prompt=prompt-1
level=INFO msg="recording prompt skipped" prompt=prompt-1
```

«Начать запись» и «Остановить» (по коду, **[владельцу]**; у строк рекордера ещё `recording=<id> pid=<pid рекордера>`, порядок может немного отличаться):

```
level=INFO msg="recorder child launched" target=exclude lead_silence=0s
level=INFO msg="capture attempt" mode=exclude ok=true ...
level=INFO msg="capture running" mode=exclude format="48000 Hz, 2 ch, 32-bit float" windows=...
level=INFO msg="recorder child" stderr="... msg=\"capture started\" ..."
level=INFO msg="capture started" recording=<id> target=exclude
level=INFO msg="recording started from the prompt" prompt=prompt-1 recording=<id>
...
level=INFO msg="capture stopped" frames=...
level=INFO msg="recorder child exited" code=0 end=""
level=INFO msg="recording finished" recording=<id> status=COMPLETED
```

Прежнего `WARN ... audiocapture: system audio capture is not available` после «Начать запись» в Windows-сборке больше нет. `msg="recorder child"` — строки лога самого рекордера.
Если process loopback не открылся: `WARN msg="capture mode switched" from=exclude to=system`, дальше запись идёт в режиме `system` (классический loopback). Если рекордер упал: `WARN msg="restarting the recorder child"` (до 3 раз); следующий сбой — `ERROR msg="capture ended by itself"`, запись заканчивается с причиной.

## 6. whisper-cli

- Скачать `whisper-bin-x64.zip` из релиза whisper.cpp с тегом `b5454` (это v1.9.5): https://github.com/ggml-org/whisper.cpp/releases/tag/b5454 ,
  SHA-256 `6ba69e3482d7826214f90a6a9c84ca07782aec1e1d0c6a7c30c994fd5d816ccb` (он же в `docs/refs/whisper.md`).
- Перед распаковкой проверить архив в PowerShell в папке, куда он скачан:
  ```powershell
  (Get-FileHash .\whisper-bin-x64.zip -Algorithm SHA256).Hash -eq '6ba69e3482d7826214f90a6a9c84ca07782aec1e1d0c6a7c30c994fd5d816ccb'
  ```
  `True` — архив тот самый (`-eq` не смотрит на регистр букв). `False` — не распаковывать и не запускать, архив удалить и скачать заново со страницы релиза.
- Из папки `Release\` архива положить рядом с `learning-assistant.exe`: `whisper-cli.exe`, `whisper.dll`, `ggml.dll`, `ggml-base.dll` и все `ggml-cpu-*.dll`. Повторная сборка заменяет только exe, эти файлы остаются.
- Что это даёт: пропадают предупреждения про whisper-cli (раздел 5) **[проверено с подставным `whisper-cli.exe` до TASK-060: при старте приложение лишь проверяет, что файл есть, и не запускает его]**, и задачи распознавания выполняются **[тест]**.
  С TASK-060 законченная запись сама создаёт задачу распознавания. Без whisper-cli задача ждёт в очереди и выполнится после установки whisper-cli и перезапуска приложения **[тест]**.
- Ещё нужна модель. Каталог встроенный и пока пустой (ни для одной модели нет проверенного SHA-256), так что «Скачать» показывать нечего **[тест]**; модель ставится импортом файла (TASK-030):
  1. Раздел «Модели», кнопка «Открыть страницу моделей whisper.cpp»: браузер открывает официальный источник https://huggingface.co/ggerganov/whisper.cpp .
  2. Для русских занятий на CPU — `ggml-small.bin` (около 466 МБ); `ggml-base.bin` (около 142 МБ) быстрее, но хуже распознаёт (размеры примерные, из README моделей whisper.cpp). Во вкладке «Files and versions» открыть страницу файла и скачать его (download).
  3. «Модели» → «Импортировать файл модели…», выбрать файл. Приложение считает SHA-256 (несколько секунд) и показывает имя, размер и SHA-256.
  4. Сравнить SHA-256 со строкой «SHA256» на странице файла на Hugging Face или с выводом `(Get-FileHash .\ggml-small.bin -Algorithm SHA256).Hash` в PowerShell. Совпадает — «SHA-256 совпадает, установить»; нет — «Отмена».
  5. Модель появляется в «Установленных». Приложение копирует файл в свою папку (`artifacts\models`), скачанный файл потом можно удалить **[тест]**. Запись, которая ждала модель, получает задачу распознавания без перезапуска **[тест]**.
- Файл, просто положенный в `artifacts\models`, приложение не увидит. whisper-cli по-прежнему ищется только при старте: положив его рядом с exe, перезапустить приложение (на странице «Модели» об этом предупреждение).
- Без модели записанная лекция не распознаётся: после «Остановить» задача не создаётся, в логе `level=WARN msg="transcription waits: no speech recognition model installed"` **[тест]**.

## 8. Что потыкать

Всё в этом разделе — **[владельцу]**, если не помечено иначе. Для опытов: `--data-dir` с одноразовой папкой.

Главное окно:
1. Запуск: окно «Learning Assistant» (1024x720), слева кнопки «Записи», «Модели», «Домашние задания», «Расписание», «Подключения», «Настройки»; открыты «Записи».
2. «Домашние задания»: заголовок и «Раздел появится в следующих версиях.» «Модели», «Расписание» и «Подключения» — ниже.

## 9. Известные проблемы

- **Папка данных занята.** Лог: `level=ERROR msg="run application" err="app: single-instance guard: instancelock: the data directory is used by another instance"`, код 1 **[проверено, `--headless`]**; с окном перед текстом будет `app: ui shell: wails: open core: `, окно не появится (по коду). Значит, на этой папке уже работает другая копия (возможно, без окна). Найти: `tasklist /FI "IMAGENAME eq learning-assistant.exe"`; закрыть её (`Quit`, Ctrl+C или Диспетчер задач).
- **Путь к папке данных с «чужими» символами и whisper-cli.** whisper-cli получает пути в кодировке Windows (ANSI; на русской Windows — 1251: кириллица подходит, а, например, китайские иероглифы нет). Если путь не помещается в неё и whisper-cli лежит рядом с exe, в логе `level=ERROR msg="speech recognition is not available" err="whispercli: invalid configuration: work directory: whispercli: invalid input: path is not representable in the ANSI code page 1251 of this system"`; приложение работает, распознавание недоступно **[проверено]**. Обход: `--data-dir` с латинским путём. Без whisper-cli будет только обычное предупреждение.
- **Скрипт не нашёл инструмент:** `'go' was not found on PATH` или `'npm' was not found on PATH` — установить Go / Node.js и открыть новый терминал.
- **Ошибка при старте с окном:** окно может не появиться, диалога ошибки пока нет — смотреть лог. Если в логе `background work did not start`, окно и настройки работают, но задачи не выполняются до перезапуска.
- **После обрыва** (Диспетчер задач, сбой) следующий запуск нормален: блокировку сняла Windows, в логе `startup recovery finished` с числами восстановленного.
- **Два процесса `learning-assistant.exe` во время записи** — это нормально: второй — рекордер (в Диспетчере задач, вкладка «Подробности», командная строка `--recorder --data-dir ...`); блокировку папки он не берёт и сам завершается после «Остановить». Если приложение оборвали во время записи, рекордер закрывает текущий кусок и выходит сам примерно за 3 с; убивать его не нужно. Прерванную запись восстанавливает следующий запуск (`found an interrupted recording`, `recording recovery finished recordings=1`) (по коду, **[владельцу]**).
