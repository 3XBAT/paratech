# Альфа-сборка: собрать, запустить, проверить

Пробная сборка десктопного приложения для Windows 10/11. Инсталлятор — раздел 11.
Пометки: **[проверено]** — проверено запуском exe или тестом при подготовке этой инструкции;
**[владельцу]** — видно только на экране, проверить вручную.

## 1. Что нужно

- Go 1.26.9 или новее (версия указана в `paratech/go.work`). Более старый Go сам скачает нужную версию (`GOTOOLCHAIN=auto` по умолчанию).
- Node.js 22 с npm (как в CI).
- WebView2 входит в Windows 10/11, ставить не нужно.
- Права администратора не нужны. Скрипт ничего не устанавливает; из сети качаются только пакеты npm, модули Go (в их обычные кэши) и архив whisper.cpp (раздел 6).

## 2. Сборка

Из корня репозитория в PowerShell:

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\paratech\desktop\build-alpha.ps1 -Smoke
```

`-ExecutionPolicy Bypass` действует только на этот запуск, политика системы не меняется.

Что делает скрипт:
1. Кладёт в папку exe компонент распознавания (`whisper-cli.exe` и его DLL, раздел 6).
2. Проверяет, что `go` и npm (сначала `npm.cmd`, иначе `npm.exe`) есть в PATH (если нет — понятная ошибка, ничего не ставит).
3. `npm ci` и `npm run build` в `paratech\desktop\frontend` (интерфейс — главное окно и попап — встраивается в exe).
4. `go build -tags production -trimpath` с `CGO_ENABLED=0`, `GOOS=windows`, `GOARCH=amd64`. Переменные ставятся только на время сборки, потом возвращаются прежние значения.
5. Через `go version -m` проверяет, что exe собран с `-tags=production` и `CGO_ENABLED=0`.

Результат: `paratech\dist\alpha\learning-assistant.exe` (около 26 МБ). Папка `paratech\dist\` игнорируется git, после сборки `git status` чистый **[проверено]**.
Другая папка: `-OutDir $env:USERPROFILE\la-alpha`. Лучше брать папку внутри профиля: в папку в корне диска (`D:\...`) могут писать другие пользователи компьютера и подменить exe.

`-Smoke` (можно не указывать) — проверка без окна: exe запускается с `--headless` и папкой данных `paratech\dist\alpha\smoke-data` (не ваши реальные данные), скрипт ждёт до 60 с строк `instance lock acquired`, `secrets_profile=isolated` и `background work started`, печатает лог (он же в `paratech\dist\alpha\smoke.log`) и останавливает процесс. Ошибка, если строк нет или в логе есть `level=ERROR` **[проверено]**.
С TASK-072 смоук до запуска сверяет 13 файлов компонента рядом с exe с закреплёнными SHA-256, ждёт ещё `speech recognition engine ready` и падает, если в логе `speech recognition is not available` **[владельцу]**.
Остановка в смоуке жёсткая (`Stop-Process -Force`): из PowerShell нельзя послать Ctrl+Break одному процессу без окна. Для тестовой папки это безопасно: блокировку снимает Windows, база при следующем запуске восстанавливается из журнала (файлы `-wal`/`-shm`). Мягкая остановка проверена отдельно (раздел 3).

## 3. Запуск и остановка

Из корня репозитория:

```powershell
.\paratech\dist\alpha\learning-assistant.exe
```

Открывается главное окно, в трее появляется иконка (стандартная иконка Wails, своей пока нет) **[владельцу]**.
Лог пишется в консоль (stderr) и с TASK-058 в файл `logs\desktop.log` в папке данных (раздел 4).

Флаги (`--help` печатает список) **[проверено]**:
- `--log-level debug` — подробнее (по умолчанию `info`; есть ещё `warn`, `error`). Отладочные строки самого Wails не пишутся: в них были бы аргументы вызовов, в том числе пароль почты и ключ Hub.
- `--data-dir $env:LOCALAPPDATA\la-test` — другая папка данных, например одноразовая для опытов. Путь только абсолютный. Тоже лучше внутри профиля, а не в корне диска (`C:\temp\...`): там её могут читать и менять другие пользователи компьютера.
  У другой папки свои секреты (ADR-0014): ключ Hub, пароль почты, клиент и вход Google вводятся в ней заново, секретов папки по умолчанию она не видит и не меняет. В Credential Manager её записи называются `paratech-<профиль>/...`: с другой папкой каждое имя `paratech/…` в этой инструкции читается как `paratech-<профиль>/…`. Профиль — 16 знаков, с `--log-level debug` он в строке `credential manager profile id` (`secrets_profile_id=`). После удаления папки записи остаются; убрать их — Диспетчер учётных данных → Учётные данные Windows или `cmdkey /delete:LegacyGeneric:target=paratech-<профиль>/mail/smtp-password` (имя — всё после `Target:` в `cmdkey /list`).
- `--headless` — без окна и трея (для проверок).
- То же через переменные `LA_LOG_LEVEL`, `LA_DATA_DIR`, `LA_HEADLESS`; флаг важнее переменной.
- `--recorder` — служебный: так приложение само запускает рекордер (раздел 7); руками не запускать (по коду).
- Неизвестный флаг, неверный уровень или относительный путь: строка `desktop: config: ...` и код выхода 2.

Лог в файл (в Windows PowerShell 5.1 без мусора `NativeCommandError`):

```powershell
cmd /c ".\paratech\dist\alpha\learning-assistant.exe --log-level debug 2> .\paratech\dist\alpha\run.log"
```

Консоль при этом пустая; файл открыть после выхода из приложения **[проверено перенаправление на `--help`]**.

Остановка:
- трей, правый клик, `Quit` **[владельцу]**;
- Ctrl+C в консоли, из которой запущено приложение. Go обрабатывает Ctrl+C и Ctrl+Break одинаково: Ctrl+Break, посланный программой процессу `--headless`, дал в логе `gracefully stopped` и код выхода 0 **[проверено]**; Ctrl+C руками **[владельцу]**;
- крестик главного окна не выходит, а прячет окно в трей **[владельцу]**;
- при запуске двойным щелчком рядом откроется консоль с логом (exe консольный). Её закрытие тоже завершает приложение; надёжнее `Quit` в трее.

## 4. Где данные

`%LOCALAPPDATA%\LearningAssistant` (обычно `C:\Users\<имя>\AppData\Local\LearningAssistant`), создаётся при первом запуске **[проверено на одноразовой папке]**:
- `learning-assistant.db` — база SQLite (настройки, записи, задачи); рядом `learning-assistant.db-wal` и `-shm`, пока приложение работает или если его оборвали;
- `learning-assistant.lock` — блокировка «один экземпляр на папку»; файл не удаляется, это нормально;
- `logs\desktop.log` — лог (по 5 МБ, старые — `desktop.1.log`, `desktop.2.log`; TASK-058, по коду);
- `artifacts\` — файлы приложения: `recordings`, `transcripts`, `models`, `exports` (кроме `recordings` пока пустые);
- `artifacts\recordings\<id>\chunk-NNNNNN.wav` — куски записи по 60 с; текущий, пока пишется, — `chunk-NNNNNN.wav.partial`. После «Остановить» рядом итоговая дорожка `artifacts\recordings\<id>.wav` (16 кГц, моно), куски остаются (по коду, **[владельцу]**).

Только в режиме с окном (по `docs/refs/wails.md` и коду Wails, при подготовке не запускалось):
- кэш WebView2 в `%AppData%\learning-assistant.exe` (папка по имени exe);
- ключей уведомлений Windows в реестре приложение больше не пишет (TASK-065). Сборки до TASK-065 оставили ключи `HKCU\Software\Classes\AppUserModelId\Learning Assistant`, `HKCU\Software\Classes\CLSID\<GUID>` и `HKCU\SOFTWARE\Learning Assistant\NotificationCategories`; данных приложения там нет, оставить их безвредно.

Сброс: выйти из приложения (`Quit`), переименовать или удалить папку `%LOCALAPPDATA%\LearningAssistant`; при следующем запуске создастся пустая. Для опытов удобнее сразу `--data-dir` с одноразовой папкой. Секреты в Credential Manager при удалении папки не удаляются (раздел 3).
По желанию можно удалить и папку `%AppData%\learning-assistant.exe`; старые ключи реестра выше для сброса трогать не нужно.

## 5. Как выглядит успешный старт

В начале каждой строки `time=...`. Запуск `--headless` на чистой папке **[проверено]**:

```
level=INFO msg="desktop core started" log_level=info headless=true
level=INFO msg="instance lock acquired"
level=INFO msg="credential manager profile" secrets_profile=default
level=WARN msg="speech recognition is not available: whisper-cli and its libraries are missing or do not verify" state=missing
level=WARN msg="transcription jobs wait in the queue until the speech component is installed"
level=INFO msg="startup recovery finished" requeued=0 completed=0 failed=0 unregistered=0 corrupt=0 conflicts=0 errors=0
level=INFO msg="background work started"
level=INFO msg="recording recovery finished" recordings=0
```

Главное — `instance lock acquired` и `background work started`. С `--data-dir` другой папки вместо `secrets_profile=default` — `secrets_profile=isolated` (профиль — только в строке уровня DEBUG `secrets_profile_id=<16 знаков>`). В папке по умолчанию в логе должно быть `secrets_profile=default`; иначе приложение не видит её секретов (ключ Hub, почта, Google) — проверьте лог. Восстановление записей идёт в фоне, поэтому последние две строки могут идти в любом порядке. Две строки `WARN` без компонента распознавания нормальны (раздел 6): про недоступное распознавание и `transcription jobs wait in the queue until the speech component is installed` **[тест]**.
С окном (по коду; **[владельцу]** сверить): `headless=false`, после предупреждения про whisper-cli строка `ui shell starting`, остальное в том же порядке; между ними могут быть строки оболочки Wails.
Планировщик и попап запускаются молча, своих строк при старте нет.
При выходе: `desktop core stopping`, затем `gracefully stopped` **[проверено]**.

Попап из трея (раздел 8) пишет в лог (по коду, **[владельцу]** сверить; названия занятий в лог не попадают):

```
level=INFO msg="ad-hoc recording prompt offered" prompt=prompt-1
level=INFO msg="recording prompt skipped" prompt=prompt-1
```

«Начать запись» и «Остановить» (по коду, **[владельцу]**; у строк рекордера ещё `recording=<id> pid=<pid рекордера>`, порядок может немного отличаться):

```
level=INFO msg="recorder child launched" target=exclude lead_silence=0s
level=INFO msg="capture attempt" mode=exclude ok=true ...
level=INFO msg="capture running" mode=exclude format="48000 Hz, 2 ch, 32-bit float" windows=...
level=INFO msg="recorder child" stderr="... msg=\"capture started\" ..."
level=INFO msg="capture started" recording=<id> windows=... build=... target=exclude mode=exclude app="" target_pid=... device=... format=...
level=INFO msg="recording started from the prompt" prompt=prompt-1 recording=<id>
...
level=INFO msg="capture stopped" frames=...
level=INFO msg="recorder child exited" code=0 end=""
level=INFO msg="recording finished" recording=<id> status=COMPLETED
```

Прежнего `WARN ... audiocapture: system audio capture is not available` после «Начать запись» в Windows-сборке больше нет. `msg="recorder child"` — строки лога самого рекордера.
Для выбранного приложения `target=include app=<exe>`; что значат поля — `docs/qa/compat-matrix.md`, «Подготовка». Если process loopback не открылся или даёт одни нули: `WARN msg="capture mode switched" from=exclude to=system cause=activation_failed` (или `cause=healthy_but_mute`), дальше запись идёт в режиме `system` (классический loopback). Если рекордер упал: `WARN msg="restarting the recorder child"` (до 3 раз); следующий сбой — `ERROR msg="capture ended by itself"`, запись заканчивается с причиной.

## 6. Компонент распознавания (whisper-cli)

- Вручную ничего качать не нужно: `build-alpha.ps1` и инсталлятор кладут рядом с `learning-assistant.exe` закреплённый набор whisper.cpp `b5454` — `whisper-cli.exe` и 12 DLL. Список, размеры и SHA-256 — в `paratech/desktop/internal/app/speechcomponent.json`, описание — `docs/refs/whisper.md`, «Speech recognition component».
- Скрипт качает официальный `whisper-bin-x64.zip` в `paratech\dist\cache\speech-component\b5454\` (следующая сборка берёт его оттуда, если размер и SHA-256 совпали), проверяет архив до распаковки и достаёт только эти 13 файлов, каждый тоже с проверкой. Из архива ничего не запускается. Старые файлы whisper в папке exe сначала удаляются **[проверено: скачивание, проверка, распаковка, `whisper-cli.exe --help`; изменённый архив отклоняется до распаковки]**.
- Без интернета: `-WhisperZip <скачанный whisper-bin-x64.zip>` или `-WhisperDir <его папка Release>`, проверки те же **[проверено]**. `-SkipWhisper` — сборка без компонента (например, чтобы проверить кнопку установки).
- Если компонента нет или файл повреждён, на «Моделях речи» и в «Записях и задачах» — «Компонент распознавания речи не установлен» и кнопка «Установить компонент распознавания». Приложение само качает тот же архив, проверяет SHA-256 и ставит файлы в `<папка данных>\components\speech`; распознавание включается без перезапуска, ждущие задачи выполняются (по коду; **[владельцу]**).
- Ещё нужна модель. В разделе «Модели речи» — список всех моделей whisper.cpp — полные и уменьшенные, с нагрузкой на компьютер и фильтрами по языку и нагрузке (размеры и SHA-256 — в `docs/refs/whisper.md`, «Model catalog») **[тест]**.
  Для русских занятий на CPU брать отмеченную «Рекомендуется для русского» (small, на экране около 181 МБ); base (около 57 МБ) быстрее, но хуже распознаёт.
  «Скачать» качает файл в приложении с официального Hugging Face, показывает прогресс и проверяет SHA-256; модель появляется в «Установленных» **[проверено живым тестом LA_MODEL_DOWNLOAD_LIVE_TEST на Windows: base, SHA-256 совпал]**.
  Запись, которая ждала модель, получает задачу распознавания без перезапуска **[тест]**.
- Раздел «Другие модели», кнопка «Открыть страницу моделей на Hugging Face», открывает в браузере https://huggingface.co/ggerganov/whisper.cpp . Скачанный там файл ставится импортом (TASK-030):
  «Импортировать файл модели…» → выбрать `.bin`; приложение показывает имя, размер и SHA-256 — сравнить со строкой «SHA256» на странице файла или с `(Get-FileHash .\<файл>.bin -Algorithm SHA256).Hash`; совпадает — «SHA-256 совпадает, установить», нет — «Отмена». Файл копируется в `artifacts\models`, исходный можно удалить **[тест]**.
- Файл, просто положенный в `artifacts\models`, приложение не увидит. Файлы whisper, положенные рядом с exe вручную, проверяются только при старте: после этого перезапустить приложение.
- Без модели записанная лекция не распознаётся: после «Остановить» задача не создаётся, в логе `level=WARN msg="transcription waits: no speech recognition model installed"` **[тест]**.

## 8. Что потыкать

Всё в этом разделе — **[владельцу]**, если не помечено иначе. Для опытов: `--data-dir` с одноразовой папкой (у неё свои секреты, раздел 3). С другой папкой каждое имя записи `paratech/…` ниже читается как `paratech-<профиль>/…` (раздел 3).
Проверка по всем критериям приёмки AC-01…AC-25 (автотесты и ручные шаги, Windows 10 и 11) — [windows-checklist.md](windows-checklist.md).

Главное окно:
1. Запуск: окно «Learning Assistant» (1024x720), слева узкая панель: «Записи и задачи», «Домашние задания», «Расписание», «Подключения», «Модели речи», внизу «Диагностика» и «Настройки»; открыты «Записи и задачи».
2. «Домашние задания» — отдельный раздел (проверка — ниже, «Домашние задания»); поиск домашнего задания по-прежнему виден задачей в «Записях и задачах». «Модели речи», «Расписание» и «Подключения» — ниже.
3. «Записи и задачи»: «Здесь появятся записи пар» с кнопкой «Импортировать расписание», ниже «Задачи» и «Задач пока нет.»; список обновляется сам каждые 3 с (пустые списки **[тест]**).
   Много записей или задач: строки в работе всегда видны, законченные — в группе «Завершённые (N)»: первые 8, «Показать ещё N», «Свернуть»; щелчок по заголовку сворачивает группу, и она не разворачивается сама при обновлении каждые 3 с.
4. «Настройки»: два переключателя, на новой папке данных оба включены: «Автоматически предлагать запись в начале занятия», «Обрабатывать только от розетки»; ниже «Тема». Выключить переключатель: сохраняется сразу, кнопки «Сохранить» нет. `Quit`, запустить снова: переключатель остался выключенным (сохранение после перезапуска **[тест]** `TestOpenCoreStoresSettings`).
5. Крестик окна: окно скрыто, иконка в трее осталась, приложение работает.

Трей:
6. Левый клик по иконке: главное окно. Правый клик: меню `Open Learning Assistant`, `Show recording popup`, `Quit`.
7. `Quit`: иконка исчезает, в логе `desktop core stopping` и `gracefully stopped`.

Попап записи (трей, `Show recording popup`; это запись без занятия, от переключателей настроек не зависит):

8. Открыть звонок или чат, выбрать в трее `Show recording popup`. Справа внизу окно без рамки 360x180 поверх остальных: «Запись без занятия», кнопки «Начать запись» и «Пропустить». Само меню трея забирает фокус у чата (так устроено меню трея в Wails), это нормально. Проверить: главное окно вперёд не выходит, попап фокус клавиатуры не получает. Пока попап виден, щёлкнуть обратно в поле ввода чата и печатать: текст идёт в чат. Настоящая проверка «попап не крадёт фокус» (AC-01) — на попапе по расписанию, после TASK-049/TASK-060.
9. Включить звук (видео, звонок), «Начать запись»: кнопка «Запуск…» (до нескольких секунд), попап скрывается. В «Записях и задачах» строка «Идёт запись», длительность растёт, есть «Остановить». В `tasklist` второй `learning-assistant.exe` — рекордер. «Остановить»: «Сохраняется», затем «Завершена». Прослушать `artifacts\recordings\<id>.wav` (раздел 4): слышен выбранный источник — только выбранное приложение или, для «Весь звук компьютера», всё, что играет компьютер, кроме самого Learning Assistant; длина как у записи. Лог — раздел 5. Если захват приложения не заработал и запись сама перешла на весь звук компьютера, у записи в «Записях и задачах» примечание (`docs/qa/compat-matrix.md`, Ж8). Убить рекордер, смена устройства и остальные проверки записи — `docs/qa/compat-matrix.md`.
   Чтобы не слышать лекцию, убавлять громкость Windows или наушников; не выключать звук вкладки, приложения или его ползунок в микшере громкости — тогда в записи тишина (ADR-0002, не проверено).
   Если не началась: попап остаётся с причиной (обычно «Не удалось начать запись.»), в «Записях и задачах» строка «Ошибка», в логе `WARN msg="recording did not start from the prompt"` с причиной.
10. «Пропустить»: попап скрывается.
11. Масштаб Windows 100% и 150%: кнопки помещаются, название занятия в одну строку с многоточием.
    Ошибка старта (выбрать приложение, закрыть его, «Начать запись») при 100%, 125% и 150%: окно вырастает вверх (до 440), ошибка и советы читаются целиком без прокрутки; в новом предложении снова 360x300.
12. Сразу после показа попапа `Quit`: процесс завершается обычно за секунды, в худшем случае до ~45 с (до 15 с на каждый из трёх шагов остановки) (`tasklist` из раздела 9 его больше не показывает).

Домашние задания (раздел «Домашние задания», TASK-045). Нужно задание: обработанное занятие, где преподаватель называет домашку (сервер обработки, раздел 7), и почта в «Подключениях». Проверка по AC-13…AC-15 — [windows-checklist.md](windows-checklist.md):
- Без заданий: «Здесь появятся домашние задания». С заданиями: строки с названием, сроком («до …» или «Без срока») и ярлыком письма («Не отправлялось», «Отправлено», «Нет подтверждения»…), кнопка «Открыть»; больше 8 — «Показать ещё N».
- Генерация: «Сгенерировать черновик» (или «Сгенерировать заново») → «Готовится черновик», затем новая версия в полях и в «Версиях». Без интернета — «Ждёт интернет» и текст про сервер обработки; лимит кончился — «Лимит обработки исчерпан»; ошибка — «Черновик не готов» с причиной.
- Правка: изменить «Заголовок» или «Текст» → «Сохранить правку» → новая версия «исправлена вручную»; «Отменить правку» возвращает текст. Пока правка не сохранена, «Сохранить в файл», «Отправить по почте…», «Сгенерировать заново» и другие версии недоступны.
- Доработка: «Дополнительные указания» («короче») и «Сгенерировать заново» → новая версия, указания видны в «Версиях»; прежние версии остаются.
- Версии: «Открыть» у старой — её текст только для чтения, «Сгенерировать заново» недоступно с пояснением «Новая версия делается из последней…»; «Взять этот текст» переносит его в последнюю версию (сохранить — «Сохранить правку»); «К последней версии».
- «Сохранить в файл» → «Версия N сохранена в файл «homework.md».» (`artifacts\exports\<id задания>\homework.md`).
- «Отправить по почте…» → окно «Отправить домашнее задание?» с «Черновик» («Версия N» — открытая версия), «Кому», «Тема», «Вложение» (имя и размер); «Отправить» — письмо уходит, в «Письмах» «Ждёт отправки» / «Отправляется» / «Отправлено <время>»; «Отмена» или Esc — письма нет. Нет адреса получателя — окна нет, только причина.
- Отправка не завершилась (сбой ядра при подтверждении): окно остаётся, текст «Не удалось завершить отправку. Повторите — второе письмо не уйдёт…» и кнопка «Повторить»; повтор — то же письмо, не второе.
- Пока прошлое письмо задания «Нет подтверждения» или ещё в пути: «Сохранить в файл» и «Отправить по почте…» — текст «…Пока оно не решено, файл задания менять нельзя.», окна отправки нет, файл не изменён.
- Неясный исход (сеть пропала во время отправки): «Нет подтверждения» и «Письмо отправлено, но подтверждение не получено…»; приложение само не повторяет. «Письмо дошло» или «Отправить ещё раз…» (своё окно с предупреждением, что письмо может прийти дважды).
- Название `<b>x</b>` в задании или черновике показывается буквально, без жирного.

Импорт расписания (раздел «Расписание»). Файл для опыта, `test.csv` в UTF-8 (дата — сегодня, начало — через 3-4 мин по местному времени, зона — своя):

```csv
title,date,start,end,timezone,uid
Математика,2026-10-15,21:05,21:50,Europe/Moscow,math-1
```

- «Выбрать файл…»: открывается окно Windows «Открыть» поверх главного, фильтр ICS/CSV/XLSX; «Отмена» в нём — ничего не меняется, ошибки нет.
- Выбрать `test.csv`: в превью счётчики «Добавится: 1», «Изменится: 0», «Удалится: 0», «Без изменений: 0», «Ошибки: 0», кнопки «Применить» и «Отмена». Испортить дату в файле (`2026-13-40`) и выбрать снова: «строка 2, колонка date: …», кнопки «Применить» нет, «Ничего не будет записано: …».
- Видны заметки: события ICS на весь день пропускаются; колонки и шаблон CSV; без `uid` изменение названия, даты или начала выглядит как «удалено + добавлено»; уведомлений импорт не показывает.
- «Применить»: «Расписание обновлено: добавлено 1, изменено 0, удалено 0.», превью исчезает. Выбрать тот же файл ещё раз: «Изменений нет…», «Применить» нет. Поменять в файле только время конца и выбрать: счётчик «Изменится: 1», в группе «Изменятся» до → после.
- Название вида `<b>x</b>` показывается буквально, без жирного.
- ICS (экспорт из Google Calendar): показан период «с … до …» (UTC), занятия вне его не удаляются.
- Большое расписание (сотни занятий, например экспорт учебного календаря): сверху счётчики «Добавится / Изменится / Удалится / Без изменений / Ошибки»; в каждой группе («Добавятся», «Изменятся», «Удалятся», «Пересечения») первые 8 строк и «Показать ещё N», после него «Свернуть»; щелчок по заголовку группы сворачивает её, «Свернуть всё» — все группы. «Применить» и «Отмена» видны внизу окна без прокрутки. Попап по расписанию (после «Применить» с занятием, начинающимся в ближайшие 5 мин, при включённом «Автоматически предлагать запись»): заголовок «Начинается занятие», название и время занятия, «Через 5 минут», сам скрывается в конце занятия. Здесь же настоящая проверка «попап не крадёт фокус» (AC-01): печатать в чате, пока попап появляется.

Модели (раздел «Модели речи»; файл модели — раздел 6):
- Новая папка данных: предупреждение «Модель не установлена: записи не распознаются…»; без компонента распознавания ещё и «Компонент распознавания речи не установлен» с кнопкой «Установить компонент распознавания». В «Рекомендуемых моделях» — шесть моделей с подписями («Рекомендуется для русского», «Быстрее, но менее точная», «Точнее, но медленнее», «Только английский»), размером, скоростью на CPU и кнопкой «Скачать»; у самой большой — предупреждение о размере и скорости.
- «Скачать» у base: прогресс, «Остановить скачивание», затем модель в «Установленных».
- «Другие модели» → «Открыть страницу моделей на Hugging Face»: браузер по умолчанию открывает huggingface.co/ggerganov/whisper.cpp (через explorer.exe).
- «Импортировать файл модели…»: окно Windows «Открыть» поверх главного, фильтр «Модель распознавания (*.bin)»; «Отмена» в нём — ничего не меняется, ошибки нет.
- Выбрать `ggml-small.bin`: несколько секунд «Выбор файла… считается SHA-256», затем имя файла, размер (около 465 МБ) и SHA-256. Он равен выводу `Get-FileHash` (регистр букв не важен). Название и версия заполнены (`small`, `1`).
- «SHA-256 совпадает, установить»: «Модель установлена: small 1.», модель в «Установленных», размер тот же; у единственной модели метка «Используется» или «По умолчанию».
- Отказы с понятным текстом: пустой `.bin` — «Файл пустой…»; файл заменён другим между показом SHA-256 и подтверждением — «Файл изменился после проверки…» **[тест]**; тот же файл ещё раз — «…уже установлена» или «Этот файл уже используется…». Переименованный в `.bin` посторонний непустой файл приложение не распознаёт как чужой (формат не проверяется): его отличает только SHA-256, не совпадающий с Hugging Face, — нажать «Отмена». Если такой файл всё же установить, задача распознавания ждущей записи завершится ошибкой, и эта запись не распознается заново сама даже после установки правильной модели (любая задача распознавания записи блокирует новую, TASK-060); поэтому сравнивайте SHA-256 до подтверждения.
- Больше 8 моделей: в «Установленных» первые 8, «Показать ещё N», затем «Свернуть»; выбор не сбрасывается обновлением каждые 2 с.
- Две модели: «Сделать по умолчанию» у другой модели делает её моделью по умолчанию и переносит метку «По умолчанию». Без модели по умолчанию — предупреждение, что распознавание ждёт выбора.
- «Удалить» → окно «Удалить модель?» → «Удалить модель»: модель пропадает (Esc или «Отмена» — ничего не меняется). Пока задача распознавания с этой моделью не закончена — «Модель нельзя удалить: её использует незавершённая задача распознавания».
- С whisper-cli: запись без модели, «Остановить», затем импорт — в «Записях и задачах» появляется «Распознавание речи» без перезапуска.
- Уйти в другой раздел во время подсчёта SHA-256 или на шаге подтверждения и вернуться: подтверждения нет, нужно выбрать файл заново; уход во время «Установка…» установку не отменяет.
- Масштаб 100% и 150%: SHA-256 переносится, кнопки и строки помещаются.

## 9. Известные проблемы

- **Папка данных занята.** Лог: `level=ERROR msg="run application" err="app: single-instance guard: instancelock: the data directory is used by another instance"`, код 1 **[проверено, `--headless`]**; с окном перед текстом будет `app: ui shell: wails: open core: `, окно не появится (по коду). Значит, на этой папке уже работает другая копия (возможно, без окна). Найти: `tasklist /FI "IMAGENAME eq learning-assistant.exe"`; закрыть её (`Quit`, Ctrl+C или Диспетчер задач).
- **Путь к папке данных с «чужими» символами и whisper-cli.** whisper-cli получает пути в кодировке Windows (ANSI; на русской Windows — 1251: кириллица подходит, а, например, китайские иероглифы нет). Если путь не помещается в неё и компонент распознавания на месте, в логе `level=ERROR msg="checking the speech component failed" err="speechcomponent: detect: speech recognition could not be activated: app: speech recognition engine: whispercli: invalid configuration: work directory: whispercli: invalid input: path is not representable in the ANSI code page 1251 of this system"` (текст по коду); приложение работает, распознавание недоступно, на «Моделях речи» — «Компонент распознавания установлен, но не запустился…» без кнопки установки. Обход: `--data-dir` с латинским путём. Без компонента будут только обычные предупреждения.
- **Скрипт не нашёл инструмент:** `'go' was not found on PATH` или `'npm' was not found on PATH` — установить Go / Node.js и открыть новый терминал.
- **Ошибка при старте с окном:** окно может не появиться, диалога ошибки пока нет — смотреть лог. Если в логе `background work did not start`, окно и настройки работают, но задачи не выполняются до перезапуска.
- **После обрыва** (Диспетчер задач, сбой) следующий запуск нормален: блокировку сняла Windows, в логе `startup recovery finished` с числами восстановленного.
- **Два процесса `learning-assistant.exe` во время записи** — это нормально: второй — рекордер (в Диспетчере задач, вкладка «Подробности», командная строка `--recorder --data-dir ...`); блокировку папки он не берёт и сам завершается после «Остановить». Если приложение оборвали во время записи, рекордер закрывает текущий кусок и выходит сам примерно за 3 с; убивать его не нужно. Прерванную запись восстанавливает следующий запуск (`found an interrupted recording`, `recording recovery finished recordings=1`) (по коду, **[владельцу]**).

## 10. Google Календарь: вход и синхронизация

Вход и выход (TASK-050) и синхронизация занятий в отдельный календарь «Learning Assistant» (TASK-051). Всё здесь — **[владельцу]**: нужны настоящий Google и браузер. Подробности и ссылки на страницы Google — `docs/refs/google-calendar.md`, решения — ADR-0011. С `--data-dir` другой папки каждое имя записи `paratech/…` ниже читается как `paratech-<профиль>/…` (раздел 3).

1. Google Cloud Console (https://console.cloud.google.com), один раз:
   - создать проект; APIs & Services → Library → Google Calendar API → Enable;
   - Google Auth Platform → Branding: название приложения, почта поддержки; Audience: **External**, статус публикации остаётся **Testing**; Audience → Test users: свой Gmail (и каждого тестировщика, до 100);
   - Data Access → Add or Remove Scopes: `https://www.googleapis.com/auth/calendar.app.created` → Save;
   - Clients → Create Client → тип **Desktop app** → Create. Сразу скопировать client ID и client secret: секрет целиком показывается только один раз.
2. Открыть «Подключения», нажать карточку «Google Календарь» (ярлык «Не настроено»): вставить идентификатор и секрет, «Сохранить»: «Клиент Google сохранён…», у «Клиент Google» ярлык «Задан», оба поля пустые. В Диспетчере учётных данных → Учётные данные Windows записи `paratech/google/client-id` и `paratech/google/client-secret` (с `--data-dir` другой папки — `paratech-<профиль>/google/...`, раздел 3). Идентификатор и секрет не класть в репозиторий и в файлы конфигурации в нём. Идентификатор не на `.apps.googleusercontent.com` — понятный текст, идентификатор в поле остался.
3. «Войти через Google»: открывается браузер по умолчанию, в приложении «Ожидание входа в браузере…» и «Отменить». Выбрать тестовый аккаунт, на экране «Google не проверил это приложение» — «Дополнительно» → перейти (небезопасно), разрешить доступ к календарю. В браузере страница в стиле приложения (светлая или тёмная, как в Windows): галочка, «Вход выполнен», «Можно закрыть эту вкладку и вернуться в приложение» и кнопка «Открыть Paratech».    «Открыть Paratech»: браузер может спросить, открыть ли приложение, — разрешить; окно приложения выходит вперёд, больше ничего не происходит. Ссылку регистрирует само приложение при старте (ADR-0013).
   «Отменить» во время ожидания — «Вход отменён.»; отказ в Google — в браузере «Доступ не разрешён» с подсказкой, в приложении «Вы не разрешили доступ в Google.». Другая ошибка — «Вход не выполнен» с подсказкой нажать «Войти через Google» ещё раз.
4. С `--log-level debug` (раздел 3) в `run.log` нет ни секрета клиента, ни токенов (искать часть секрета, `ya29.` и `1//` — так начинаются токены Google).
5. «Выйти»: «Вы вышли из Google, доступ приложения отозван.», у «Вход» ярлык «Не выполнен», записи `paratech/google/refresh-token` в Диспетчере нет. На https://myaccount.google.com/linkedapps приложения больше нет (Google может убрать его не сразу). Без сети: «Доступ удалён из приложения, но Google не подтвердил отзыв…» — отозвать там же вручную.

12. «Выйти», «Войти через Google» тем же аккаунтом, «Синхронизировать»: календарь «Learning Assistant» по-прежнему один.
13. Удалить календарь «Learning Assistant» в Google Calendar (Настройки → календарь → «Удалить»), «Синхронизировать»: появился новый «Learning Assistant» со всеми занятиями.
14. Изменить или удалить событие занятия в Google Calendar: занятие в приложении не меняется (AC-20); после правки этого занятия в файле и импорта событие перезаписано.
15. Дедлайн: когда появится экран подтверждения (TASK-045), подтвердить предложение «дедлайн в календарь» — в «Learning Assistant» событие дедлайна на 15 минут; повторное выполнение не создаёт второго.
16. Без интернета «Синхронизировать»: «Нет связи с Google…»; с интернетом в течение минуты — «Календарь «Learning Assistant» синхронизирован.», время «Последняя синхронизация» новое, рядом «· N попытки», если были повторы.
17. С `--log-level debug` в `run.log` нет токенов (`ya29.`, `1//`) и названий занятий в ошибках.

Проверить на живом Google (в документации не сказано; результат записать в `docs/refs/google-calendar.md`):
- Удалить событие занятия в Google Calendar и изменить это занятие в файле, импортировать, «Синхронизировать»: событие вернулось (PUT со `status: confirmed` восстанавливает удалённое)? Если нет — только это занятие остаётся несинхронизированным, остальные записываются; задача повторяется с ошибкой «calendar sync skipped some lessons … google calendar kept the event deleted».
- Удалить занятие (событие удалено приложением), вернуть в файл с тем же `uid`, импортировать: занятие новое, событие создаётся (вставка с id удалённого события отвечает 409, и приложение делает PUT)?
- Что отвечают `calendars.get` и `calendarList.get` про удалённый календарь и после входа другим аккаунтом (404 или 403): в обоих случаях должен появиться новый календарь (шаг 13 и вход другим аккаунтом).

Известно:
- В режиме Testing вход действует 7 дней, потом сохранённый доступ не работает: синхронизация показывает «Вход в Google истёк: войдите снова…» (красная строка результата), а карточка «Google Календарь» на обзоре — «Нужен вход» («Нет доступа», если при входе не разрешили доступ к календарю); войти заново: «Войти через Google» (или «Выйти», затем «Войти через Google»).
- Если приложение упало сразу после создания календаря в Google, при следующей синхронизации может появиться второй, пустой «Learning Assistant» — его можно удалить.
- В новый календарь (шаг 13) старые дедлайны не возвращаются: они пишутся только при подтверждении предложения.
- Вход другим аккаунтом и обратно (A → B → A) или новый клиент Google (шаг 1): в аккаунте A появляется второй «Learning Assistant», а в первом остаются прежние события (дубли). Первый удалить вручную.
- Google удаляет клиент Desktop app, которым не пользовались 6 месяцев; тогда создать новый (шаг 1) и сохранить его в приложении.

## 11. Инсталлятор

`build-alpha.ps1` остаётся для exe разработчика (разделы 2–3). Для тестеров — инсталлятор, его собирает владелец; подробности и источники — `docs/refs/packaging.md`.

1. Один раз поставить NSIS 3.x: https://nsis.sourceforge.io/Download, открыть новый терминал.
2. Проверка без сборки (NSIS не нужен) **[проверено]**:
   ```powershell
   powershell -NoProfile -ExecutionPolicy Bypass -File .\paratech\desktop\build-release.ps1 -DryRun
   ```
   Печатает версию, найденные `makensis`, `go`, `npm`, WebView2 и команды. Без NSIS — `makensis: NOT FOUND` и ссылка; без `-DryRun` скрипт тогда падает сразу, до сборки **[проверено]**.
3. Сборка: та же команда без `-DryRun`. Компонент распознавания скрипт кладёт в инсталлятор всегда (раздел 6); без интернета — `-WhisperZip` или `-WhisperDir`. **[владельцу]**
4. Результат: `paratech\dist\release\learning-assistant-<версия>-windows-amd64-setup.exe` (размер и SHA-256 в конце вывода). Версия — из `paratech\desktop\VERSION`; в сам exe она не попадает: в `about.json` пакета для поддержки — `(devel)` и коммит git.
5. Установка без прав администратора в `%LOCALAPPDATA%\Programs\LearningAssistant`, ярлык «Learning Assistant» в меню «Пуск». Данные — там же, где у альфы (раздел 4). Проверки после установки — [windows-checklist.md](windows-checklist.md), раздел «Инсталлятор».
6. Exe в инсталляторе консольный, как и альфа: при запуске из «Пуска» рядом открывается консоль с логом, её закрытие завершает приложение. Выходить — `Quit` в трее. Лог есть и в `%LOCALAPPDATA%\LearningAssistant\logs\desktop.log`, так что сборка без консоли возможна — это следующий шаг, не в этой задаче.
7. Обновление — новый инсталлятор поверх старого (автообновления нет). Удаление — «Приложения и возможности»; на вопрос «Удалить и ваши данные?» ответ по умолчанию «Нет».
