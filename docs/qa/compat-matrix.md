# Матрица совместимости записи звука (Windows 10/11)

Здесь видно, какие сборки Windows, способы захвата и ситуации проверены с настоящим звуком, и как проверить остальное.
Автотесты к звуковым устройствам не обращаются (раздел «Что нельзя автоматизировать»), поэтому всё здесь проверяется вручную.
Связано: TASK-058 (диагностика), TASK-059 (выбор приложения), ADR-0002 (audio capture). Таблица Verification в ADR-0002 — сценарий
TASK-016 для спайка `capturespike`, а эта матрица — для exe альфы, и статусы ведутся здесь. Сборка и запуск альфы — `docs/qa/run-alpha.md`.

Статус в ячейке:
- «не проверено» — на этой сборке с настоящим звуком никто не проверял;
- «проверено вручную, Р-N» — проверено, а дата, сборка (`winver`), тестер и результат записаны в строке Р-N «Журнала»;
- «не проверено (без звука, З-N)» — на этой сборке измерено только то, что описано в З-N, а настоящий звук не проверялся.

Сейчас всё «не проверено». На Windows 10 19045 без звука измерено только то, что описано в З-1…З-3.

| 26200 | Windows 11 25H2 | ПК с 25H2. Известный дефект: process loopback активируется, но даёт одни нули ([MeetCap #38](https://github.com/lybym/MeetCap/issues/38)); здесь ждём автоматический переход (Ж8) |
| 26H2+ | Windows 11 26H2 и новее | Hyper-V VM из ISO Windows 11 Enterprise Evaluation 26H2 (нужен вход с учётной записью Microsoft; номер сборки не подтверждён) |

- VM: Hyper-V поколения 2, vTPM, Secure Boot, 4 ГБ памяти. Своей звуковой карты у VM нет. Для устройства вывода поставить VB-CABLE (звук в колонки не идёт) или подключаться через Enhanced Session: там появляется устройство «Remote Audio», звук слышен на ПК (что loopback на нём работает — не подтверждено). Записанный WAV скопировать на ПК и прослушать. На время работы VM остановить Docker (`wsl --shutdown`): 16 ГБ памяти на всё сразу не хватит.
- В VM нельзя проверить Bluetooth, проводные наушники, настоящие драйверы (Realtek, HDMI) и сон: такие сценарии помечены «ПК».
- CI (GitHub: `windows-2022` = 20348, `windows-2025` = 26100, `windows-11-arm` = 26200) только собирает и запускает тесты без звука.

## Способы захвата

| Код | Что | Как выбрать | В строке `capture started` |
|---|---|---|---|
| П | приложение: process loopback INCLUDE дерева процессов выбранного приложения (основной) | в попапе выбрать приложение | `target=include mode=include app=<exe>` |
| К | весь звук компьютера: process loopback EXCLUDE самого Learning Assistant, при сбое С | в попапе «Весь звук компьютера» | `target=exclude mode=exclude app=""` |
| С | классический loopback устройства вывода по умолчанию (запасной, с keep-alive) | в приложении сам не выбирается: только после автоматического перехода (Ж8), строка «Весь звук компьютера (классический)» в «Проверить звук» (Ж1) или спайк `capturespike -mode system` (ADR-0002, Verification) | `mode=system` |

**Эталон** — OBS 28 или новее: источник «Application Audio Capture» («Захват звука приложения») на то же окно, рядом «Desktop Audio» для сравнения с С.
OBS использует тот же API Windows: если наш результат отличается от OBS, это наш баг (ADR-0002, Verification).

## Подготовка (для всех проверок)

1. Собрать и запустить альфу (`docs/qa/run-alpha.md`, разделы 2–3). Для опытов можно взять одноразовую папку данных: `--data-dir $env:LOCALAPPDATA\la-test`.
2. Номер сборки: Win+R → `winver` (вида 19045.6456). Он нужен для журнала.
3. Лог: `%LOCALAPPDATA%\LearningAssistant\logs\desktop.log` (с `--data-dir` — `<папка>\logs\desktop.log`). Открыть в Блокноте, искать через Ctrl+F. Блокнот сам не обновляет открытый файл: закрыть и открыть заново.
4. Начать запись: трей, правый клик → `Show recording popup` → выбрать источник в списке → «Начать запись». Остановить: главное окно, «Записи и задачи» → «Остановить».
5. Дорожка — самый новый `%LOCALAPPDATA%\LearningAssistant\artifacts\recordings\<id>.wav`, слушать в любом плеере. Куски по 60 с лежат в `recordings\<id>\`.
6. Строка старта (искать `msg="capture started" recording=`):
   ```
   level=INFO msg="capture started" recording=<id> windows="Windows 10 Pro 22H2 (10.0.19045.xxxx)" build=10.0.19045.xxxx target=include mode=include app=chrome.exe target_pid=<pid> device="Динамики (Realtek(R) Audio)" format="48000 Hz, 2 ch, 32-bit float"
   ```
   `target` — что просили, `mode` — чем пишется сейчас, `device` — устройство вывода по умолчанию. Строка `msg="recorder child" ... stderr="..."` — это лог самого рекордера, не она.
   Строки о дочернем процессе (`recorder child`, `capture attempt`, `capture mode switched`, `capture stopped`) после `msg="..."` сначала несут `recording=<id> pid=<pid>`, поэтому ниже там стоит `...`.
7. Попытки открыть захват: `msg="capture attempt" ... mode=... ok=true ... device=...` и `level=WARN msg="capture attempt failed" ... mode=... hresult=0x... error=...`.
   Переход: `level=WARN msg="capture mode switched" ... from=include to=system cause=<причина> reason=...`, где причина — `activation_failed`, `healthy_but_mute` или `stream_failed`.
8. Если что-то не так: «Диагностика» → «Сохранить пакет для поддержки…», zip приложить к строке журнала.

## Шаги

«Ожидается» без пометки подтверждено документацией или исследованием. Пометка «ожидание, не подтверждено» значит, что так должно быть по логике, но источника нет:
результат может оказаться другим, и его тоже нужно записать.

**А1. Defender, SmartScreen.**
1. Загрузить `learning-assistant.exe` на облачный диск и скачать браузером: только у скачанного файла есть метка «из интернета», exe, собранный на этом же ПК, SmartScreen не проверяет.
2. Запустить двойным щелчком. Дословно записать предупреждение SmartScreen («Система Windows защитила ваш компьютер» → «Подробнее» → «Выполнить в любом случае»), предупреждение браузера при скачивании и записи Defender (Безопасность Windows → Журнал защиты).
3. Начать запись: рекордер — тот же exe с флагом `--recorder`.
- Ожидается: SmartScreen предупреждает, потому что exe не подписан; Defender может ложно срабатывать на Go-программы (тогда записать название угрозы). Второго предупреждения при старте записи нет (ожидание, не подтверждено).

**Б1. Список приложений.**
1. Открыть браузер с играющим видео, Zoom/Teams/Телемост (что есть) и Блокнот.
2. Трей → `Show recording popup`, раскрыть список.
3. Закрыть или открыть приложение, закрыть и снова раскрыть список (пока список раскрыт, он не обновляется).
- Ожидается: первым идёт «Весь звук компьютера» (значок «ПК»), дальше приложения: иконка (или первая буква) и название окна. Одно приложение — одна строка, сколько бы окон у него ни было. Самого Learning Assistant в списке нет.
  У играющего — «звучит» (метка появляется только после первого звука приложения). Список обновляется за ~3 с. Длинные названия обрезаются, прокрутки в попапе нет.
- Лог: при сбое `audio sessions could not be read; the apps are listed without them`, и тогда меток «звучит» не будет.

**Б2. Подсказки и запомненное приложение.**
1. Выбрать браузер: «Записывается звук всего браузера, со всех вкладок. Другие видео включайте в другом браузере или приложении.» Всегда есть и общий совет: «Чтобы не слышать лекцию, убавьте громкость Windows или наушников…» (если подсказок несколько, они свёрнуты в строку).
2. «Начать запись», через минуту «Остановить». Снова открыть попап: браузер выбран сам.
3. `Quit`, запустить приложение и открыть попап: браузер выбран. Если браузер закрыт, выбран «Весь звук компьютера», а браузер выбирается сам, как только появится в списке.
- Лог: `capture started ... target=include mode=include app=<exe браузера>`.

**Б3. Приложения из Microsoft Store.**
1. Открыть приложение из Store со звуком (например, «Кино и ТВ» с видео).
2. В списке оно показано под своим именем и с иконкой, а не как `ApplicationFrameHost.exe`.
3. Записать 1 мин и прослушать.
- Ожидается: звук приложения записан (ожидание, не подтверждено).

**Б4. Приложение закрыто перед стартом.**
1. Выбрать в попапе Zoom (или другое приложение) и, не начиная запись, полностью закрыть его (и из трея тоже).
2. Подождать ~3 с: у приложения появляется «приложение закрыто».
3. «Начать запись».
- Ожидается: попап остаётся с текстом «Выбранное приложение не запущено. Откройте его или выберите другое.»
- Лог: `level=WARN msg="recording did not start from the prompt"`.

**Б5. Перезапуск приложения во время записи.**
1. Браузер с видео, выбрать его, «Начать запись».
2. Через минуту закрыть все окна браузера; в Диспетчере задач процесса браузера быть не должно. Подождать 20 с.
3. Открыть браузер, включить видео. Через минуту «Остановить».
- Ожидается: всё это время в «Записях и задачах» «Идёт запись»; в дорожке звук, потом ~20 с тишины, потом снова звук. OBS переподключается так же.
- Лог: `capture target exited; waiting for the app`, затем `capture target re-bound by exe name` (`old_pid`, `new_pid`), `stopping the recorder child to capture the new instance of the app` и новый `recorder child launched` с `target=include`.
  После 20 перезапусков за одну запись: `the app restarted too often; the capture waits without following it`, дальше пишется тишина.

**Б6. Масштаб 100% и 150%.**
1. Параметры → Система → Дисплей → Масштаб; если вид не изменился, перезапустить приложение.
2. В попапе выбрать браузер и выключить его в микшере, чтобы появилась подсказка про микшер. Затем выбрать закрытое приложение и нажать «Начать запись», чтобы появился текст ошибки.
- Ожидается: кнопки «Начать запись» и «Пропустить» видны полностью, тексты переносятся. Прокрутка допустима только внутри области текста и только в крайнем случае.

**Б7. Фокус (AC-01).**
1. Импортировать расписание с занятием через 3–4 мин (`docs/qa/run-alpha.md`, раздел 8, «Импорт расписания»); флажок «Автоматически предлагать запись» должен быть включён.
2. Щёлкнуть в поле ввода чата (Telegram, браузер) и печатать, пока появляется попап «Начинается занятие» и пока обновляется его список.
- Ожидается: текст продолжает идти в чат, главное окно вперёд не выходит. После щелчка по попапу фокус у попапа — это нормально.

**В1. Динамики (база).**
1. Видео с речью в Chrome. В OBS добавить «Application Audio Capture» на окно Chrome и «Desktop Audio».
2. П: выбрать Chrome, записать 2 мин. К: выбрать «Весь звук компьютера», записать 1 мин. Во время записи включить звук уведомления Windows.
3. С: спайк `capturespike -mode system` (ADR-0002, Verification, шаг 1) и строка «Весь звук компьютера (классический)» в «Проверить звук» (Ж1).
4. Прослушать. За время записи каждые 60 с появляется новый кусок `chunk-*.wav`, `.partial` есть только у текущего.
- Ожидается: речь звучит во всей дорожке, длина дорожки равна времени записи. В П слышен только Chrome (уведомления нет), в К — всё, кроме самого Learning Assistant.
- Лог: `capture started` с `mode=include` (П) или `mode=exclude` (К), в `device` — ваши динамики, `format="48000 Hz, 2 ch, 32-bit float"`. Строки `capture mode switched` нет.

**В2. Проводные наушники.**
1. П (Chrome с видео), 3 мин. Через минуту вставить наушники (3,5 мм или USB), ещё через минуту выдернуть.
2. Повторить для К. Для С — спайк (ADR-0002, Verification, шаг 7).
- Ожидается: П и К не привязаны к устройству и пишут без перерыва (ожидание, не подтверждено). Если Chrome сам не перешёл на новый выход, звука не будет — проверить по OBS.
  С переоткрывает устройство за ~2 с, пропуск заполняется тишиной.
- Лог: для П и К новых строк нет; появление `restarting the recorder child` или `capture ended by itself` — сбой, записать. Для С (если запись перешла на С сама): `capture attempt ... mode=system ok=true ... device="<новое устройство>"`, в пакете поддержки `capture.json` `reopens` больше 0.

**В3. Bluetooth A2DP.**
1. Подключить BT-наушники и выбрать их выводом: Параметры → Система → Звук → Вывод «Наушники» (стерео), не «Головной телефон».
2. П (Chrome), 3 мин: через минуту выключить наушники, через 30 с включить. Повторить для К.
3. «Проверить звук» с наушниками (Ж1).
- Ожидается: звук в записи есть до и после (ожидание, не подтверждено); пока наушники выключены, Chrome играет в динамики или молчит. В `device` строки `capture started` — имя наушников.

**В4. Bluetooth HFP (звонок).**
1. BT-гарнитура с микрофоном, звонок в Zoom (или Teams, Телемост) с её микрофоном: Windows переводит гарнитуру в режим разговора (звук хуже).
2. П: выбрать Zoom, записать 2 мин звонка. Затем П: Chrome с лекцией во время звонка. Повторить для К.
3. С: спайк (ADR-0002, Verification, шаг 7, `-exe Zoom.exe`).
4. «Проверить звук» во время звонка, но не во время записи (Ж5).
- Ожидается: П записывает собеседника (ожидание, не подтверждено). С на Windows 10, скорее всего, тишина: там «Головной телефон» — отдельное устройство (в Windows 11 устройство одно).
- Лог: `device` — имя гарнитуры в режиме разговора («Головной телефон…», «Headset…»).

**В5. Смена устройства по умолчанию.**
1. Два выхода (динамики и наушники или HDMI; в VM — VB-CABLE и Remote Audio). П (Chrome), 3 мин.
2. Значок звука в трее → выбрать другое устройство, через минуту вернуть прежнее. Повторить для К; для С — спайк (шаг 7).
- Ожидается: П и К пишут без перерыва, если Chrome сам перешёл на новое устройство (ожидание, не подтверждено); новых строк в логе нет.
  С при каждой смене пишет в лог `capture attempt ... mode=system ok=true ... device="..."`, а `reopens` в `capture.json` больше 0.

**Г1. Громкость Windows 0, mute динамика.**
1. П (Chrome с видео), 2 мин: через 30 с громкость Windows 0, ещё через 30 с вернуть громкость и нажать mute, ещё через 30 с снять mute.
2. Повторить на каждом выходе (динамики, проводные, HDMI, BT) и для К. Для С — спайк (шаг 2) и «Проверить звук» при громкости 0.
3. Сравнить уровень с «Application Audio Capture» и «Desktop Audio» в OBS.
- Ожидается: в П и К звук в записи на полной громкости, хотя вы его не слышите (по исследованию «скорее да», не подтверждено). С на некоторых устройствах (HDMI, некоторые USB и BT) замолкает.

**Г2. Микшер.**
1. Chrome с видео. Открыть микшер: правый клик по значку звука → «Открыть микшер громкости» (Windows 11: Параметры → Система → Звук → Микшер громкости).
2. Выключить Chrome в микшере и открыть попап: у Chrome «звук выключен в микшере», подсказка «Звук этого приложения выключен в микшере Windows: запись будет пустой…». Снова включить.

- Ожидается: уровень записи следует за ползунком, при 0 и mute тишина (как в OBS). Строки `capture mode switched` нет: заглушённое приложение не запускает переход на С.

**Г3. Заглушённая вкладка.**
1. Лекция во вкладке Chrome, П (Chrome), 1 мин: через 20 с правый клик по вкладке → «Отключить звук на сайте», ещё через 20 с включить.
2. Повторить в Edge, Firefox и Яндекс Браузере, выбирая в списке соответствующий браузер.
- Ожидается: пока вкладка заглушена, в записи тишина: браузер сам закрывает свой звук в Windows. Приложение этого не видит, предупреждает только общий совет. Строки `capture mode switched` нет. В OBS так же.

**Г4. Другое видео.**
1. П (Chrome): (а) лекция в Chrome, другое видео в Edge; (б) лекция и видео в двух вкладках Chrome; (в) вкладка с лекцией заглушена, другая вкладка играет. По 1 мин.
2. К: лекция в Chrome и видео в Edge.
- Ожидается: (а) записана только лекция; (б) записано и то и другое; (в) записано только видео (худший случай). В К записано всё.

**Д1. Zoom, Teams, Телемост.**
1. Источник звука: в Zoom — zoom.us/test или «Проверить динамик», в новом Teams — «Пробный звонок», в Телемосте — звонок со второго устройства. Затем те же встречи в браузере (Meet, Телемост).

  Новый Teams в 2023 году в OBS молчал: проверить отдельно (не подтверждено).

**Е1. Сон и пробуждение.**
1. П (Chrome с длинным видео), 10 мин. Через 2 мин: Пуск → Завершение работы → Спящий режим; через 2 мин разбудить и включить видео.

- Записать: статус в «Записях и задачах» после пробуждения, есть ли звук после пробуждения, строки лога после пробуждения: `capture mode switched ... cause=stream_failed`, `restarting the recorder child` (например, `reason="the recorder child sent nothing for 30s"`), `capture ended by itself`.

**Е2. Блокировка экрана.**
1. П, 5 мин: через минуту Win+L, через 2 мин войти снова.
- Ожидается: запись не прерывается, звук есть всё время (ожидание, не подтверждено).

**Е3. Приватность микрофона.**

**Е4. Запись 3 ч.**
1. Длинный плейлист в Chrome, П, 3 ч. Диспетчер задач → Подробности: процесс `learning-assistant.exe` с `--recorder` (столбец «Командная строка»). Записать его память и ЦП через 5 мин, 1 ч и 3 ч.
2. «Остановить».
- Ожидается: ~180 кусков, дорожка ~3:00:00 (16 кГц моно, ~345 МБ). Память рекордера не растёт, ЦП 1–2% и меньше (у спайка ~0,6% одного ядра). Строки `restarting the recorder child` нет.
- Лог: `capture stopped ... frames=<N>`. При формате 48000 Hz N / 48000 должно быть ≈ 10 800 с; записать разницу.

**Е5. Рекордер убит.**
1. Идёт запись П, 2–3 мин. PID рекордера есть в строке лога `recorder child launched ... pid=<pid>`.
2. В PowerShell: `taskkill /F /PID <pid>`.
3. Ещё трижды убить новый рекордер (PID брать из нового `recorder child launched`).
- Ожидается после первого раза: запись идёт дальше, в логе `level=WARN msg="restarting the recorder child" recording=<id> restart=1 delay=1s reason="the recorder child exited unexpectedly (code 1)"` (код может быть другим) и новый `recorder child launched`.
  Нумерация кусков продолжается, пропуск в дорожке заполнен тишиной, один `.partial` остаётся и в дорожку не входит.
- После четвёртого раза запись заканчивается с причиной (`capture ended by itself`), приложение не падает. Убить само приложение и прочее — `docs/tasks/TASK-017-recorder-manual-checks.md`.

**Ж1–Ж7. «Проверить звук».** Главное окно → «Диагностика» → «Проверить звук».
- Тон 1 кГц около 1,5 с звучит вслух на устройстве вывода по умолчанию, ответ приходит не позже чем через 15 с («Проверка занимает до 15 секунд.»).
- Ответ — текст итога, «Устройство вывода: <имя>» и под «Способы записи» две строки: «Захват приложения» (process loopback собственного тона) и «Весь звук компьютера (классический)» (С), у каждой «Работает» или «Не работает» с причиной («Сигнал не слышен.», «Не поддерживается в этой системе.» и т. п.).
- Итог считается для источника, выбранного последним: для приложения — по строке «Захват приложения»; для «Весь звук компьютера» итог «Звук записывается…», если хотя бы одна строка «Работает».
- Тон играет сам Learning Assistant. Поэтому проверка показывает, что на этой сборке Windows захват работает, но не что слышно выбранное приложение (заглушённую вкладку она не найдёт).
- Лог: `sound check child launched`, `sound check child exited ... code=0`, затем `msg="sound check" device="..." hands_free=false include=<причина> system=<причина> include_hresult=...` и `msg="sound check" source="<источник>" verdict=<итог>` (источник `whole computer` или `app <exe>`).

| ID | Как вызвать | Ожидаемый текст | В логе |
|---|---|---|---|
| Ж1 | динамики или проводные наушники, громкость любая | «Звук записывается: проверочный сигнал слышен.», обе строки «Работает» | `include=ok system=ok` |
| Ж2 | Панель управления → Звук → Воспроизведение: «Отключить» на каждом устройстве (или выдернуть единственное USB-устройство); потом включить обратно | «Нет устройства вывода звука. Подключите динамики или наушники и повторите проверку.» | `include=no_device` |

| Ж4 | только на сборке, где process loopback не запускается (ожидается ниже 19041; на 19045 запускается, З-1) | «Этот способ захвата звука не работает в этой системе. Запись сама перейдёт на весь звук компьютера, если он доступен.» | `include=unsupported include_hresult=0x...` |

**Ж8. Автоматический переход на С.**
Переход случается сам на сборке, где process loopback даёт нули (ожидается на 26200) или не запускается. На 19045 вручную его не вызвать: логику проверяют автотесты на фейковом рекордере (`TestWASAPIStreamFallsBackWhenHealthyButMute`, `TestWASAPIStreamSwitchesWhenProcessLoopbackFails`, `TestRecordingNotesTheFallbackOfTheRecorderChild`) и на синтетических показаниях счётчиков (`TestMuteDetector`, `TestAudioExpected`).
«Звук играет» значит: у аудиосессии, которую захватывает этот способ, есть уровень (П — сессия выбранного приложения, К — сессия любого приложения, кроме самого Learning Assistant). Нули должны идти 15 с подряд; паузы до 5 с счёт не сбрасывают, тишина дольше 5 с начинает его заново.
1. П (Chrome с видео, звук не заглушён), 2 мин. Повторить для К.
2. Найти в логе переход:
   - если захват давал нули при играющем Chrome, через 15 с появится `level=WARN msg="capture mode switched" ... from=include to=system cause=healthy_but_mute reason="healthy but mute: only zeros for 15s while the app played"` (для К: `from=exclude`, `while other apps played`);
   - если не запустился — `capture attempt failed ... mode=include ... hresult=0x...`, затем `capture mode switched ... cause=activation_failed`.
3. В течение ~15 с появится `capture fell back to the system output; noted on the recording`, а в «Записях и задачах» под статусом записи: «Захват выбранного приложения давал только тишину, хотя звук играл (only silence) — записывается весь звук компьютера.»
   (или «… не запустился (activation failed) — …», «… прервался (stream failed) — …»). Для К: «Основной захват звука компьютера … — записывается звук устройства вывода по умолчанию.»
- Ожидается: запись не останавливается; после перехода в дорожке звук всего компьютера; примечание остаётся и после «Завершена».
- Перехода не должно быть, когда приложение или вкладка заглушены (Г2, Г3): иначе в запись попали бы чужие звуки. Для К — и в тишине (Ж10).

**Ж9. Пакет для поддержки.**
1. `capture.json` хранит только записи текущего запуска, поэтому сначала (пере)запустить приложение с `--log-level debug` (`Quit`, затем снова), потом подготовить данные: в «Подключениях» задать пароль почты, ключ Hub и адрес почты; импортировать расписание с названием урока (например, «Математика»); сделать одну запись под видео с запоминающимся названием; если есть распознанный текст, запомнить из него фразу. Пакет сохранять в этом же запуске.
2. «Диагностика» → «Сохранить пакет для поддержки…». Открывается окно Windows «Сохранение пакета для поддержки» с именем `paratech-support-ГГГГММДД-ЧЧММСС.zip` и типом «Архив ZIP (*.zip)».
   «Сохранить» → «Сохранено: <имя>» и «Пакет для поддержки сохранён. Приложение ничего не отправляет: передайте файл разработчикам сами.» «Отмена» → «Сохранение отменено.»
3. Распаковать: правый клик → «Извлечь всё». Внутри должны быть только `about.json`, `settings.json`, `capture.json`, `logs\desktop.log` (и `desktop.1.log`, `desktop.2.log`, если они есть). Файлов `.wav`, `.db` и папки `artifacts` нет.
4. Открыть каждый файл в Блокноте и искать (Ctrl+F): пароль почты, кусок ключа Hub (8 и больше символов), полный адрес почты (допустимо только `***@домен`), название урока, фразу из распознанного текста, название окна с видео, имя пользователя Windows (пути должны начинаться с `%USERPROFILE%`). Ничего из этого найтись не должно. Имена устройств звука (`device`) в пакете есть: они нужны для диагностики.
5. В `about.json` версия и сборка Windows совпадают с `winver`, есть версия приложения. В `settings.json` адрес Hub только в виде `https://хост[:порт]`. В `capture.json` для последних записей есть способ, устройство, попытки, переходы и `reopens`.
- Автотест `TestSupportBundleHoldsNoSecrets` проверяет то же на образцах; эта проверка — на настоящих данных.

**Ж10. Весь звук компьютера в тишине.**
Детектор «здоровый, но немой» для К смотрит только на звук других приложений, поэтому тишина в начале записи не должна вызывать переход.
1. Закрыть всё, что играет звук. В попапе выбрать «Весь звук компьютера», «Начать запись».
2. 30 с ничего не включать, затем видео в Chrome на 1 мин. «Остановить».
- Ожидается: в дорожке 30 с тишины, потом видео. Строки `capture mode switched` нет, у записи в «Записях и задачах» нет примечания. Если переход был — записать строку `capture mode switched` с `reason` и приложить пакет поддержки.

## Что нельзя автоматизировать и почему

| Проверка | Почему только вручную |
|---|---|
| Любой настоящий звук (В, Г, Д, Ж1–Ж5) | на CI-раннерах GitHub нет звуковых устройств, Windows 10 там нет вообще; виртуальный кабель поставить можно, но будет ли loopback отдавать тон — не подтверждено |
| Bluetooth A2DP и HFP (В3, В4, Ж5) | нужны настоящий адаптер и гарнитура; в VM и на CI Bluetooth нет |
| Громкость 0 и mute на разных устройствах (Г1) | результат зависит от драйвера (Realtek, HDMI, USB): от него зависит, где стоит отвод у С; виртуальный кабель этого не покажет |
| Сон, пробуждение, блокировка (Е1, Е2) | нужны живая сессия пользователя и управление питанием; на CI так нельзя, в VM это не то же самое |
| Zoom, Teams, Телемост, заглушённая вкладка (Г3, Д1) | нужны вход в аккаунт, собеседник и окна на экране |
| Что в дорожке речь, а не шум | нужен слух. Есть полуавтомат по флагу (играет тон вслух): `$env:LA_AUDIO_LIVE_TEST=1; go -C paratech test -run TestLive -v ./desktop/internal/adapters/audiocapture/; Remove-Item Env:LA_AUDIO_LIVE_TEST` |
| Вид попапа, фокус, SmartScreen (Б6, Б7, А1) | видно только на экране; SmartScreen проверяет только скачанный файл |
| Запись 3 ч (Е4) | без устройства не имеет смысла, а на CI слишком долго |
| Приватность микрофона (Е3) | меняет системные настройки пользователя |
